# Tabs Design System

An accessible, reusable **Tabs** component with an optional **Badge**, built as a slice of a
design system: tokens first, framework-agnostic CSS, and the WAI-ARIA APG Tabs pattern
implemented from scratch (no headless UI libraries).

## How to navigate

- **Components/Tabs → Docs** — hand-written page: when to use it, controlled vs uncontrolled,
  variants, badges, keyboard support and the full props tables.
- **Components/Tabs → stories** — `Pill` and `Underline` (the two variants), `WithBadge`,
  `Mobile` and `Overflow` (horizontal scrolling tablist), `SwitchingTabs` (controlled example).
- **Components/Badge → Docs** — generated from the component; one story per variant
  (`Neutral`, `Positive`, `Negative`) plus `AllVariants`.
- The **Accessibility** panel runs axe on every story, including the colour-contrast checks
  that jsdom cannot perform in unit tests.

## Principles

- **Semantic tokens.** Colours, spacing and typography come from `src/tokens` as CSS custom
  properties, named after Figma (`SurfaceHigh` → `--ds-color-surface-high`). Components never
  hardcode a colour or a spacing value.
- **Framework-agnostic CSS.** Plain SCSS with BEM classes under a `ds-` prefix
  (`ds-tab`, `ds-tab--pill`, `ds-tab__label`) — no CSS Modules, no CSS-in-JS, so the same
  stylesheet can back more than one framework.
- **Accessibility by construction.** Roving tabindex, arrow/Home/End navigation with automatic
  activation, panels that stay mounted so `aria-controls` always resolves, and a selected state
  styled from `[aria-selected="true"]` so the visual and the accessible state cannot diverge.
- **Responsive without props.** Mobile is a media query (≤ 768px), never a prop.

The README in the repository root documents the API decisions, the Figma inconsistencies and
the testing strategy in full.
